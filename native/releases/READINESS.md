## Blocking a new upload / App Store readiness claim

- App-specific privacy/support content is in separate review. Existing website/upvote privacy pages are not Couch Clash policies. No placeholder URL is bundled or published.
- Home automatically fetches scores on open and on Refresh. Names, team labels, predictions, host outcomes, themes and game saves stay local and are not in requests. The service receives ordinary network/request metadata; Read-only aggregate inspection found28 retained Supabase Edge invocation records with non-empty IP, user-agent, city/country/region/postal/timezone, URL/path, response status and duration fields; no visitor values were retrieved. Disclose this operational network/location-related metadata separately from local gameplay. Exact Edge/internal retention, drain inventory, owner export/use purposes and App Store linkage/tracking classification remain unverified. Free-plan general API/database log pricing does not establish an exact Edge deletion period. GitHub Pages web access separately logs visitor IPs. Do not infer “Data Not Collected” from local gameplay storage. The offline build4 disclosure is a separate assessment.
- Backend source forwards no client headers/IP to BALLDONTLIE and stores game DTOs, not gameplay. No custom console logging was found. Infrastructure log fields are now evidenced; retention and use remain separately under review; do not invent deletion or retention promises.
- `PrivacyInfo.xcprivacy` carries forward the old declaration as a review input, not a validated declaration for this candidate. Inspect the final Release archive, actual SDK/API use and Xcode privacy report. Swift uses SwiftUI/WebKit/Foundation; no third-party SDK/package dependencies or direct UserDefaults usage have been introduced. JavaScript localStorage alone does not justify guessing a required-reason API declaration.
- Owner-approved support/privacy URLs, App Store privacy answers, age/content ratings, metadata, current screenshots, review contact and release decisions remain pending. No response SLA is promised.
- Physical iPhone/iPad, VoiceOver, larger text and actual airplane-mode recovery remain unverified. Simulator failure injection is not physical offline verification. No external beta review or App Review submission is authorized.
- New explicit product requirements are Apple integration and app-wide player/team leaderboards. Game Center and Sign in with Apple are distinct options under separate research; the user clarified “groups of groups competing together.” Proposed scope is players → groups → larger teams, with standings at each level and size-fair scoring; aggregation rules are not yet approved. Game Center is not SSO; Sign in with Apple plus an authoritative shared store is under separate research, with optional native Game Center projection. No Apple capability, identity provider, shared room, ranking backend or trusted competition is configured. Manual/demo/host-defined outcomes must never enter trusted app-wide rankings; the current free feed lacks original first-score/play detail needed to validate all existing prediction calls.
- Shared-room and identity requirements remain product gaps: current game is one-phone pass-and-play with editable local names. No account/authentication, separate-phone sync or remote host exists.
