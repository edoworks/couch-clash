# Couch Clash — sanitized product review edition

Recovered 2026-10-05. This is a selected, redacted review edition of an existing requirements snapshot, not a verbatim canonical file and not proof of the exact native build-3 source. Personal context, account identifiers, private artifact references, authorization history and operational coordination are omitted. Product requirements below preserve their historical scope; shared-room and future-model requirements do not imply they shipped in build 3. See EVIDENCE-STATUS.md and PROVENANCE.json.

## Product
A one-phone football prediction game for 2–6 players. Editable generic names, original graphics and system typography. No money, prizes or assumed team allegiance.

## Experience
1. Choose the verified Seahawks–Chargers fixture (Oct 4, 2026, 1:25 PM Pacific), or clearly marked simulated rehearsal. Fixture status is scheduled until kickoff, then 'status unverified'; never inferred live.
2. Edit 2–6 player names. Pass-and-play: each player opens a private card, makes three picks, optionally boosts one, and locks. Unanswered picks are allowed only through explicit skip; score zero.
3. Pregame calls: first team to score in the first half (100), first-half first scoring play (100), winner including tie (100). One pregame boost doubles one correct call, no penalty for a miss. Lock before kickoff; resolve early calls at halftime and winner at final.
4. Halftime: two fast calls, second-half scoring leader and combined second-half points band (200 each). Lock before third-quarter play. Maximum total score 800. No speed scoring; shared ranks on ties.
5. Host manually records outcomes from the broadcast; results preview precedes confirmation. Void/cancelled calls give zero to everyone. Demo uses fixed invented outcomes with explicit simulation labels.
6. End podium shows shared winners, full score breakdown, replay/reset.

## More fun, less screen: acceptance criteria
- Each player card has at most three prompts; no clocks, pressure mechanics, notifications, or attention loop.
- Clear handoff curtain conceals picks from the next player until reveal. This is courtesy privacy, not authentication.
- Lock is explicit and irreversible within the match; host cannot score an open round.
- Every score is explainable, misses/skips/voids give zero, ties share rank.
- Touch controls at least 44px; keyboard navigation, visible focus, reduced motion, usable at 390×844 and 320px wide.
- Reload preserves progress; storage failure visibly warns; reset erases only this app's data.
- Self-contained assets work offline once cached on localhost/HTTPS; LAN HTTP can keep a loaded page running offline but cannot install a service worker.

## Native implementation requirements
Bundled WKWebView gameplay assets must work without runtime network dependencies. Restrict navigation to bundled content; approved external schedule and glossary links open in the system browser only after a user tap. Preserve persistent local storage, native safe-area layout and an original app icon. Simulator checks do not establish physical-device acceptance.

### Identity and fair play
- Shared rooms require each host/participant to sign in with Apple to a distinct Couch Clash account. Keep editable display names separate from verified account identity; do not expose Apple identifiers or email to the room. Use the same application account across native/web through properly associated Apple identifiers and verified server tokens, never email/name matching. Keep local demo/pass-and-play clearly separate.
- An invite admits a player, never the host role. Server-owned memberships authorize every operation. Host cannot read unrevealed opponent picks, write another player's card, impersonate by name, reopen a locked card, or directly edit score totals. Picks lock transactionally against the room's current round/version; late or replayed writes fail.
- The game server computes scores from locked picks plus versioned outcomes. Preserve an append-only room-visible outcome/correction log with actor/time/old/new/reason. Corrections never erase prior versions; mark pending/disputed results and saved-history versions explicitly. This supersedes the earlier blanket prohibition on all corrections, without allowing silent overwrites.
- Apple authentication establishes an account, not truth of football events, one account per human, or immunity from collusion. Manual outcome mode stays labeled host-reported. Recommend host proposes outcomes and one other signed-in participant confirms before finalization; disagreement stays disputed, not silently resolved by the host. This reduces unilateral manipulation but is not independent verification. No verified licensed feed or trustless result claim.

### Save means two distinct things
1. **Save & resume an active game:** every member can save/bookmark the authoritative room in My Games, return on another signed-in device, and recover their role and own drafts/locked picks. Saving is not pausing the broadcast, extending a deadline, cloning the state or reopening locks. Only the host controls round progression. Display last server acknowledgement; offline edits are pending until accepted.
2. **Save final game to history:** each member can retain a versioned final summary, own picks and revealed group results in their account independently. Run it back starts a new room and does not erase retained history. Deleting a personal save does not delete other members' saves or the shared match. A saved completed match is read-only; replay creates a new game. Export is a separate optional action, proposed later; exports cannot restore authority or expose unrevealed picks/secrets.

Retention decision remains open: proposed unsaved inactive rooms expire after seven days with notice; explicitly saved active rooms remain resumable subject to an agreed limit/archive rule; saved completed summaries remain until the saving user deletes them or deletes their account. Never apply the seven-day live-room cleanup to user-retained saves silently. State storage quotas before approval. Account deletion must revoke Apple/app sessions, delete private picks/account/profile/saves and propagate removal of attributable identity/data in shared retained histories. Preserve only genuinely non-identifying aggregate results where appropriate; do not call a reversible replacement label anonymization. Exports already made cannot be recalled; disclose that before export. Define host departure: close/archive or explicitly transfer to a consenting member, not implicit takeover.

### Personal appearance
Each user chooses Default, Seahawks colors or Chargers colors; start at Default and infer no allegiance. Use original artwork and accessible color tokens, no copied logos. Preferences belong to the account with local fallback and apply only to that user's view, not the room or others' themes. Theme selection never changes fixture/team picks, role, outcomes or scores. Maintain 4.5:1 normal-text / 3:1 large-text and meaningful-control contrast, text/icon indicators beyond color, visible keyboard focus, reduced motion and usable 320px layout. Preview theme choice in Settings and restore across sessions.

### Final-state wording requirement
The final podium currently calls the winner “In the lead” and the runner-up “Still in it.” Replace final-state statuses with “Winner” / “Shared winner” / “Finished” while retaining appropriate halftime wording. This records a historical requirement; release implementation must be verified against the applicable source.

### Acceptance and rollout gates
- Host + two independently signed-in phones join one room; different display names do not create or claim another identity. Web/native account linkage, reinstall/re-login and revocation work without duplicate accounts; another account cannot read private saves.
- API tests prove host/guest cannot fetch opponent unrevealed picks, forge role or score, reopen locks, backdate/duplicate commands, or win concurrent lock/close races. Server timestamps and versions govern acceptance. Outcome proposals/corrections and dispute state are visible consistently.
- Save active game, sign out/re-login on another device and resume own state; saving after round close never grants extra picks. Final save survives replay, room cleanup and own-device reset. Personal deletion cannot erase another member's own save; account deletion removes private/identifying data and revokes access.
- All themes pass contrast/focus/reduced-motion/mobile checks on native and web; changing one user's theme leaves game state and others' views unchanged. Final standings never use active-game encouragement.
- Stage 1: agree backend/account/outcome trust/retention plan and screenshot corrections. Stage 2: implement locally and test policies/state transitions with isolated users; build web/native authentication after specifically approved Apple configuration and secret storage. Stage 3: separate approval for schema/frontend deployment and native TestFlight upload, then physical-phone invite/save/theme acceptance. No public App Store release implied.

## Beginner-help requirements
- Show each existing question’s `when` scope immediately below its title, before options and Lock. Keep those scopes unchanged, including before-halftime, extra-point exclusion, and overtime treatment.
- Put brief definitions and examples in native HTML details/summary disclosures. Help is optional and initially collapsed. Reading help must never make a pick, toggle a boost, lock a card, change an outcome, or save new state. Do not show a player's pick card or its help on the handoff screen.
- Call the 100/200 awards “prediction points”; explain they are separate from football scoreboard points. Retain the exact scoring rules and 800-point maximum.
- Hypothetical arithmetic acceptance: halftime Seahawks 14–7 Chargers; final Seahawks 21–17 Chargers → second-half Seahawks 7, Chargers 10, combined 17. Thus Chargers lead the second half and the combined band is 0–20 even though Seahawks win the game. Include overtime in this prototype’s after-halftime period. Never present this example as a real result or a statistic.
- Source link: [official NFL football glossary](https://operations.nfl.com/rules-officiating/nfl-football-basics/football-terms). Explain that external sources open online; the small in-app explanations remain available with cached app assets. No runtime AI, new feed, analytics, or telemetry.
- Preserve all existing names, selected picks, boosts, round locks, handoff privacy, v1 migration, v2 saves/history, demo/manual labels and storage keys. Keep shared-play work separate. Local web candidate only; native external-link handling must be reviewed before any native refresh or release.

### Stats and source requirements
No current statistics feed has been verified. Do not display invented stats, unsourced probabilities, stale numbers as current, or pretend manual/simulated results are live. Any future stat must store its source URL/provider, exact teams/fixture/season, definition and sample window, value/units, data-as-of timestamp with timezone, retrieval timestamp, and freshness policy. Display the as-of date and source beside it, including an explicit stale/unavailable state. Source availability and reuse/license terms must be verified before inclusion. Historical descriptive stats are not calibrated win probabilities. These are future acceptance requirements, not implemented data integrations.

### Extensibility and immutable meaning of saved games
Current saves still use positional question/option indexes and global question definitions. This beginner change deliberately leaves their order, wording, options, scopes and scoring untouched; compatibility tests pin all five definitions. This does not yet solve future catalogue/version migrations. **No team, fixture, sport, option order or scoring swap may ship until saved meaning is versioned and independent of current globals.**

Required future model: stable sport, fixture, team, question and option IDs; an explicit ruleset/schema version; immutable per-match snapshots of fixture/timezone, question text/scope, option IDs and labels, scoring/boost rules, ties/voids, and source metadata. Calculate and display saved history using its own snapshot, never the latest global catalogue. Select teams by stable ID rather than display name. Version corrections explicitly; replay creates a new match with the selected new definitions and leaves old history intact.

Legacy compatibility mapping to freeze before expansion: fixture `nfl-2026-week04-sea-lac`; ruleset `couch-football-v1`; questions in current order `first-half-first-team`, `first-half-first-play`, `final-winner`, `after-halftime-leader`, `after-halftime-total-band`. Map existing numeric options to the exact current Seahawks/Chargers/no-score, touchdown/field-goal/safety/no-score, Seahawks/Chargers/tie, Seahawks/Chargers/even, and 0–20/21–35/36+ meanings. Preserve skip/void -1 and current boost/100/200 scoring. These proposed stable IDs are specification only in this requirements snapshot, not evidence of persisted fields in build 3. Back up legacy data before a future migration; unknown versions must be rejected visibly without overwriting user data.

Other teams/sports should use explicit sport-specific periods, overtime rules, result types and help, with source-reviewed definitions. Do not reuse football halves/scoring by assumption. No runtime sport switch, multi-sport catalogue or live-fixture expansion is built here.

## Board and recap requirements

- Show a five-call prediction board automatically after all cards lock, and make it available from the public handoff curtain. Returning to picks restores the curtain, never another player's open card. Group votes/boosts/earned points appear only for calls already revealed under existing rules.
- Show settled/total plus resolved, voided and awaiting counts. An unresolved call has a text label and no outcome, pick tally or zero-score implication. Show the next real host action based on phase; do not infer broadcast progress from wall-clock time. Pregame halftime questions say they open at halftime.
- Use “Host-reported · no live feed” or “Fictional demo” consistently. Record optional per-round confirmation timestamps only when existing Confirm is pressed. Old saves show that confirmation time was not recorded; last-save time is not treated as football-data freshness.
- Preserve manual selection → review → irreversible confirmation, and the existing demo's explicitly fictional outcomes. Merely opening the board, viewing a recap or leaving an incomplete outcome desk never changes picks, scores or outcomes.
- Final recap contains shared ranks, explainable points, at most two highlights derived from fully revealed picks, and the existing complete breakdown. No “decisive” or probabilistic claim unsupported by actual arithmetic. All-zero ties, no correct picks, explicit voids and skipped picks get honest neutral copy. No autoplay, forced animation, timers or notification prompts.
- Extend the existing final-save/history views and add a direct route to the most recent saved recap from setup. Save stays explicit, read-only history survives replay, capacity remains 20 without eviction, failed saves never claim success. Prototype storage uses its own key so testing cannot overwrite published app data; copied legacy/current fixtures test compatibility without importing real personal data automatically.
- A local review artifact is not a hosted iPhone application. Publication and native distribution are separate release steps.
